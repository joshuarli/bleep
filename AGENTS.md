# blip monitor

One Vite + TypeScript frontend probes Cloudflare Workers and Vercel Fluid from the browser and plots both destinations on one timeline. `docs/` holds the detail.

## Commands

- `npm ci` — install. Deployed functions pin Node 24; local Node 26 prints `EBADENGINE`, which you can ignore.
- `npm run check` — stamp the build and type-check.
- `npm test` — stamp the build and run the `node:test` suite.
- `npm run accept:foundation` — check, test, build both providers, and run the probe contract under `workerd`.
- `node scripts/browser/check.ts all` — verify the page in a real browser against simulated fixtures.
- `node scripts/verify-live.ts --all` — verify the deployed probes, revisions, and location.

`npm run dev:vercel` serves the local Vercel probe on 8788; `npx cf dev` serves the local page and Cloudflare probe on 8787.

## Invariants

- `src/probe/handler.ts` is the only probe implementation; the provider adapters supply `ProbeSite` only.
- `scripts/stamp.ts` sets the build revision and `BLIP_TARGET` (`production`, `local`, `fixture`). Deploy refuses a dirty tree and forces `production`.
- Endpoints are fixed per target in `src/config/endpoints.ts`; the page never accepts an endpoint from a URL or user input.
- Only `ok` attempts carry latency. Failures never get zero or deadline latency.
- Percentiles use nearest rank; there is no p99 or jitter.
- Compare pairs by `pairSeq` only, and results from different UI hosts are never pooled.
- No runtime dependencies, database, accounts, server-side history, or rate limiter.
- Cloudflare deployment uses the `cf` CLI; there is no Wrangler config. Vercel stays on Node 24 Fluid in `sfo1`.
